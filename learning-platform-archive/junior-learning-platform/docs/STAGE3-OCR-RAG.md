# 第三阶段：真实本机OCR与检索评估

实施与验收：2026-11-13至2026-11-14（Asia/Shanghai）。接续第二阶段和收尾修复，保留已有文件、测试、旧math和Antigravity并行成果。没有部署、推送、生产改动、付费模型调用或真实学生资料上传。

## 1. 实际完成范围

**真实平台功能**：本机Tesseract.js 7.0.0提取中英印刷文字；私有图片/机构/关系鉴权；独立OCR记录；原文与教师修订分别保存；必须教师确认后才允许引用为阅卷来源；分值仍由教师逐题录入、整份确认。OCR不会生成知识点诊断、标准答案、成绩、复测或成长进步。

**完整DeepTutor RAG尚未连接**：本机缺相关运行依赖和模型；已进行真实上游题号检索代码实验与独立SQLite FTS5检索基线，明确区分。平台新增的src/retrieval-contract.mjs只是内部适配校验，无公开检索端点、无假成功响应、无新增知识库业务记录。

三步学习主线与线上/线下角色边界保留。OCR仅为线下教师核对提供原文，不能跳过教师关口或替代学生实际作答。

## 2. 本机运行

当前机器已安装Tesseract.js及core 7.0.0；固定语言文件已下载到忽略目录.local/ocr-models，运行时不从网络补模型。正常开发：

```powershell
cd C:\Users\Administrator\Desktop\junior-learning-platform
node scripts/setup.mjs
node scripts/setup-ocr.mjs
node scripts/dev.mjs --ocr
```

访问http://127.0.0.1:8788。没有--ocr时保持明确不可用，原有人工输入仍工作。其他机器可设置OCR_ENGINE_DIR为实际Tesseract.js 7.0.0包目录、OCR_MODEL_DIR为经核验语言文件目录。首次缺语言文件时，显式运行`node scripts/setup-ocr.mjs --download-models`；只下载固定公开文件，不发送图片。模型已有但哈希不同会保留原文件并拒绝启用，不自动覆盖。

Cloudflare Pages/Functions未绑定OCR供应方，仍返回503 OCR_UNAVAILABLE。不能把Node本机子进程成功描述成Cloudflare已经有OCR。新增迁移0003已在隔离本机D1执行；没有远程资源操作。

## 3. 来源、许可与运行边界

- 运行库：[Tesseract.js](https://github.com/naptha/tesseract.js)及core，本机package.json均为7.0.0，LICENSE为Apache-2.0。
- 语言：[tessdata_fast固定提交87416418657359cb625c412a48b6e1d6d41c29bd](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd)，eng与chi_sim约6.6MB，LICENSE一起保留。每次启动及识别前核验SHA256；清单见scripts/ocr-models.mjs。
- 本轮没有将引擎/模型复制进public或分发成发布包。今后分发应保留相应许可、版权及适用第三方声明；本轮不是全部传递依赖SBOM认证。
- 图片以字节经stdin送入本机子进程；不接受客户端路径、URL、引擎配置或模型名。Tesseract识别线程的fetch被禁用，语言与core都从本机读取。仅模型准备步骤下载公开文件。
- 单个运行器一次一任务，父进程与子进程均有45秒超时，父服务丢失时子进程仍可自行终止。Node老生代堆上限256MiB，不是整个操作系统进程内存硬配额。沿用上传2MiB/1200万像素限制，每账号5次/15分钟，失败也受限；不是跨集群费用硬上限。
- 识别stderr不返回或写业务日志，API仅输出白名单错误码。来源模型与时间留在OCR记录，审计不含图片、原文、修订文字或密钥。

旧paper-worker审计补充：它向Workers AI发送完整图片，提示词要求忽略隐私**不等于图片已脱敏**；其近似单位置限流不能充当全球费用硬上限。本阶段没有搬入那条外部传图路径，也没有复用其限流宣传。元数据清理也不等于像素脱敏；界面仍提醒先遮挡姓名/学校，本机OCR不是自动图像脱敏工具。

## 4. 数据与审核状态

ocr_runs状态为running→needs_review→teacher_confirmed，或failed。保存原文、引擎置信分、语言/版本、存储图片摘要、修订文字、教师与时间。confidence仅为引擎指标，不是正确率。

- 识别空白、失败、超时或输出过大时，不生成替代文字。失败记录可查看与导出；空记录清单禁用打印。
- requestId保证重试复用，唯一索引保证同一图片只有一个running任务。超过2分钟未完成的旧running记录在访问时标OCR_INTERRUPTED，解除阻塞；不暗中自动重跑。
- 学生可识别本人图片并看原文，但不能确认OCR文字。学生原有“人工核对上传文本”不等于教师OCR确认，不能绕过门槛。
- 教师确认文字后，`POST /papers`可带ocrRunId；仍只建立空草稿，老师须手工拆题、确认范围、录入实际满分/部分分并逐题复核。没有自动把识别中的分值变成成绩。
- paper保存最小ocrProvenance：引擎、模型版本、图片/修订文本摘要、教师与时间，不复制整份OCR原文。原图/运行记录删除后，已有确认分值与最小来源摘要保留。
- OCR记录沿用原图24小时访问期限，删除上传会级联删除OCR原文。Node的cleanup-local仍负责到期物理清理；正式R2生命周期/可靠清理未部署。
- 原uploads.ocr_status列为兼容保留；API字段由ocr_runs及真实运行能力计算，前端不可把旧列常量当成当前状态。
- 同样，旧paper.content_origin列保留原约束；API的contentOrigin按经验证的ocr_provenance_json推导。后台分析须使用这一来源规则，而非只看旧列。

新增API和示例见API.md/OpenAPI1.2.0。父母和管理员不能访问OCR原图/原文；所有读取、确认、来源引用、导出均执行原机构/学生关系鉴权。

## 5. 真实OCR效果：6张自编合成图

命令：`node scripts/experiments/ocr-local-evaluation.mjs`。本机Node24.22.1，Chrome渲染自编文字为PNG，Tesseract实际识别。不是手写题库、真实相机照片或代表性试卷数据集。

| 样本 | 归一后字符差异率 | 单次本机耗时 |
|---|---:|---:|
| 清晰英文 | 0 | 665ms |
| 清晰简中+等式 | 0 | 962ms |
| 中英混排 | 0 | 949ms |
| 根式/上下标/集合符号 | 约15.8% | 942ms |
| 轻度模糊与倾斜 | 约3.2% | 935ms |
| 空白 | 正确返回无文字 | 511ms |

指标对字符串做NFKC并去空白，**不衡量题号结构、版式、上标保真或数学等价**；0差异不等于通用100%准确率。复杂公式中√/上下标/∈出现明显错误，尽管引擎置信分为84。原始expected/recognized与图片保存在test-results/ocr/evaluation.json及同目录PNG，不能隐藏错误或用模型置信分代替准确率。

首次用数据对象作为language参数初始化失败，已改为明确本机语言路径/字符串，并禁用线程fetch，实际重跑成功；没有用模拟文本替代该失败。

详见RAG-LOCAL-EVALUATION：固定DeepTutor的exercise_lookup等4个模块实际执行15项断言，输入是明确的解析替身，不代表PDF已解析；独立SQLite FTS5真实建索引40,960字节、28项检查，8条自编查询Top1/Top3均命中6条，两条语义改写失败。无Embedding、LLM、付费或真实学生资料。

2026-11-14补充只读确认：原判分反例回归仍保留在scripts/experiments/deeptutor-module-probe.py，固定提交60fb3bdf…；已保存的.local/deeptutor-probe-result.json记录了不同整数12345678/12345679被接受、等价值0.5/1/2被拒、not correct/correct被错误接受。18/18表示这些行为（包括错误）被复现，绝不等于判分正确率。运行src没有导入该判分模块：选择题仍按已审核快照答案精确比较，卷面分仍来自教师人工录入。RAG命中/引用指标与评分正确性继续分开。此补充没有重跑已覆盖实验、修改正式判分或自动启用上游算法。
