## 浏览器实际覆盖

- 桌面 Chromium 1440×1000：六科分别实际选择诊断、阅读对应讲义、练习、复测并查看结果，验证实际计数为 0/1、1/1、1/1；检查切科后清除上一科状态。
- 手机浏览器视口 390×844 与 360×800：数学完整演示闭环、讲义、复测结果、四档切换、自定义 300 分、总和错误、单科上限、计划日期错误与有效安排；上述状态未观察到横向溢出。
- 三个视口匿名访问均只请求 `/api/v1/public/arts/catalog`，未调用会话、学生记录或私有打印接口；没有写入 `localStorage`／`sessionStorage`。实际网络请求记录在报告中。
- 未登录打开艺考工作台时，私有工作区隐藏并提示登录。
- 合成教师可建立真实低目标计划、填写基线和内部备注、核对并审核测试版本；合成学生只能看本人内容，待审版本不能开始正式作答；家长没有编辑、教师审核或实际答案详情入口，内部教师备注没有进入家长摘要。
- 用隔离 SQLite 和真实本地 API 跑通数学学生三阶段保存，页面呈现同范围 0/1 → 1/1，不生成高考预测。教师审核点击来自自动化合成账号，**不属于真人教师审核**，未写生产数据。
- 新增 390px 定向回归证明未提交练习可恢复原题组并提交，避免刷新后卡在重复创建冲突；学生已有本年度计划时不显示重复新建表单。

## 已知验证限制

- 没有进行真实手机、微信扫码内置浏览器、真实打印机或用户现场操作测试。手机尺寸测试使用桌面 Chrome 的视口模拟，不宣称真机通过。
- 浏览器主轮与后续小范围修订验证分开执行，没有在最终每次文案／打印微调后重复全部 175 项检查；后续只重跑受影响的首屏、PDF及刷新恢复流程。
- 受保护三阶段浏览器流程为数学一个点；后端六科闭环用例覆盖全部 6 个点。公开六科各自三阶段均经过桌面实际点击。
- PDF样本为语文、数学与家长摘要，不代表六科所有将来讲义的版式均已审核。
- 题目、学生和教师动作均为隔离测试数据；不据此判断真实学习效果、内容真人审核数量或正式成绩。
- 没有在本验收中更新生产数据库、替换 Worker、改动旧 math、VPS 代理或 DeepTutor。生产备份、合并、迁移与回滚验证由唯一发布流程另行记录。

## 复跑命令

```powershell
node --test tests/arts.test.mjs tests/arts-public.test.mjs
node scripts/arts-ui-test.mjs
```

浏览器脚本通过现有 `browserHarness` 启动回环服务与内存 SQLite，结束时关闭服务；PDF工具使用已配置的 Codex 捆绑 Python。脚本的教师审核只发生在每次创建的测试数据库中。
