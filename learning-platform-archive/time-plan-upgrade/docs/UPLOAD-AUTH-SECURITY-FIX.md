# 上传权限竞态补丁 upload-auth-20261114.1

2026-11-14。网站线程发现并用真实API/SQLite与暂停的对象存储适配器复现：旧POST在put等待期间撤权后仍发布记录/对象/成功审计；旧DELETE在等待期间撤权仍删除，但没有持久化的授权提交点。其原始probe与证据保留在发布副本，不覆盖。

本补丁只修改src/uploads.mjs，新增tests/uploads-race.test.mjs。没有新增迁移或修改公开请求/成功响应结构。OpenAPI仍1.6.0；新增失败码DELETE_PENDING使用既有503错误信封。网站线程收到新哈希后自行复制、回归；本线程没有上线、更改域名、改生产库或修改发布副本。

## 权限和提交点

- 原子SQL同时检查当前机构/角色、师生关系、双方active、请求会话token_hash仍存在且未过期。请求最初的allowStudent不是最终依据。
- POST：put结束后、INSERT发布点重新检查。此前撤权/退出/停用/换角色机构则不发布；补偿删除新对象。put抛错也可能写过字节，仍补偿。补偿失败时保存expires_at=0的不可访问清理记录，不写image_uploaded成功审计。
- POST提交后再撤权：允许已经授权提交的记录留给学生，但最终读取会拒绝向失权老师返回。不能因此删除已提交对象造成悬挂数据库引用。数据库提交回执丢失时先查询是否已有记录；存在或读结果不确定时不做破坏性补偿。
- GET图片：存储get返回后再读原子权限/会话，失败时停止返回并尽可能取消对象流。详情和清单在metadata异步读取后复核；墓碑不会出现。已通过最后鉴权并开始发送的数据不能追溯撤回。
- PATCH人工核对：权限、revision和有效期位于同一UPDATE；授权失败404，有权但旧版本409；成功审计只随实际写入。
- DELETE：先以带权限/revision条件的UPDATE将expires_at设0、revision递增，这是**删除接受和授权提交点**。提交前撤权404且不能调用对象delete；提交后再撤权不取消已经接受的删除，完成时200。旧probe只看到后续200/物理消失不足以判断新版本越权，须检查存储调用前墓碑和提交前交错。

不存在D1与R2/文件系统的分布式事务；本补丁明确操作顺序和失败状态，不承诺跨存储瞬时撤销已经提交的操作。

## 墓碑、重试和清理

expires_at=0在既有所有有效期查询中不可见，OCR和阅卷附件访问也已按有效期过滤。DELETE物理失败返回503 DELETE_PENDING，说明访问已停止而物理清理未完成；不恢复有效期、不谎称物理文件已删除。仍具有当前有效会话/绑定的学生或老师可再次DELETE同一ID；已撤权/退出者不能借重试越权。成功移除行后重复删除404。

导出`cleanupPendingUploads(env,{limit:25})`为**可信私有维护函数，没有HTTP路由**。它只处理expires_at=0，逐个幂等清理对象再删行，失败保留墓碑并返回pending计数；不清理活动图片。不应从前端调用或注册公开管理接口。最终行删除保留既有FK行为（OCR级联、阅卷引用置空但来源快照保留）。

审计：上传/人工核对仅实际成功时记成功；删除接受写image_delete_requested，物理删除且最终行移除后写image_deleted。重试可能再记request事件，但不重复成功事件。维护函数返回计数，不冒充用户写image_deleted；生产任务应另记录运行计数/失败告警。

网站线程尚须接入周期私有清理及监控，并验证自己的磁盘适配器/TTL扫描与备份策略。若DB和对象存储同时不可用，任何双写方案都可能留下无法即时登记的私有孤儿；仍需存储TTL/孤儿扫描。R2正式生命周期与发布磁盘清理不在本补丁中自动配置，不能仅凭本补丁把整体上传运营门槛置为通过。
