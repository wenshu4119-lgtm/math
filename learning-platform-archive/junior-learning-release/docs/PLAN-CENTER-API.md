# 学习计划中心增量接口

基于 time-plans API，不更换账号、测评、题库、讲义、评分或存储系统。所有请求继续遵守既有登录、CSRF、绑定关系及最终 SQL 授权检查。学生本人、绑定家长、绑定教师可管理计划；管理员不能查看学生学情。所有私有响应 no-store。

## 保存与来源

原 `/time-plans/preview` 配置新增 `planName`、`planKind=evidence|custom|mixed`、`customTasks`；`goal.mode=exam|routine`。旧记录缺这些字段时兼容为原检测计划，不重新解释旧成绩。

- exam：保留原上限/目标合计、湖北史地政及等级分规则。
- routine：总分、单科目标和上限均为 null，不要求日常计划填写考试分值；仍选择实际学段/科目/目标日期/年度。
- customTasks：用户材料说明/事项，不是平台审核讲义或检测证据。类型、科目、估算分钟、优先级、起止、每周重复天、线上/线下、完成标准均经验证。最多 60 条定义，重复展开不超过 300 项，总计划不超过 400 项。任务期外/休息冲突或预算不足列未排入，不自动挤入。
- 复制：preview 带 `cloneId`，必须属于同一授权孩子；生成新计划，始终为草稿。复制配置/安排和报告引用，不复制执行、复盘或真实作答。
- 首份新计划在无当前 active 时保存为 active，其余为 draft。已完成任务、锁定安排和历史记录按原规则保留。对自定材料仅提供内容说明，不生成测评/评分入口。

## 管理

`GET /time-plans/context` 继续按学生/学段/年级/年度返回，计划列表增加名称、来源类型、状态、实际执行数量、未排入数量和日期；界面支持搜索/过滤。

`POST /time-plans/:id/profile`：expectedVersion、name、status、reason；设为 active 且已有另一份 active 时，须带 expectedActiveId/expectedActiveVersion。原子暂停前份、写两边版本和审计，再激活目标。同一范围只能有一份 active，由唯一索引强制。draft/paused/completed/archived/legacy 计划均不能通过计划入口记录新执行或发起作答；历史仍可读，原学习工作台的学习权限不受参与计划与否影响。completed 表示用户结束此计划，不表示所有任务已完成/掌握。

旧版计划迁移后读取为 legacy（待设当前），不会擅自批量激活或创建资料行；用户明确保存设置或设为当前后生成资料。重排与恢复不擅自改变执行状态。保存的直接链接 `/planning/index.html?plan=<opaque-id>` 每次均经账号和绑定校验，不能作为分享授权。

## 每周复盘

`POST /time-plans/:id/reflections`：expectedVersion、requestId、weekStart（周一）、wins、difficulties、nextStep、reason、previousId（纠正时可用）。未来周不可记为已复盘；复盘保存当时计划版本、已排分钟、用户填报分钟与完成事项数的独立快照，叙述属于用户自述，不是自动计时、检测或掌握结论。

同任务取该周最近填报时长，不把多次状态切换重复累计。纠正创建新记录并链接原记录；不覆盖原文。计划查看与既有授权 PDF 含复盘，按周过滤；日清单不混入整周叙述。

## 模块视图与隔离

计划卡片 → 当前执行计划 → 今日/周计划/月历/任务清单/复盘/制定与调整。列表折叠后优先呈现执行内容。不同学段、年级和年度不混合日历；只在选定范围计算一份当前预算，不声称跨所有范围已做全局冲突排查。

新增 `0051_plan_center.sql` 仅添加 time_plan_profiles（含范围唯一 active 索引）和 time_plan_reflections，不重建已有表。迁移脚本逐表核对旧数据/结构，拒绝残缺新 schema，支持重复执行。回滚保留这些表；旧前端不提供新模块管理能力。

本次不接入额外题库报告、不扩大题量、不启用外部 AI、自动消息、收费或安卓。自定义任务可以服务初一至初三和艺考日常学习，但不能因此称这些年级均已完成平台真实检测报告适配。
